# Validation record — 12 October 2026

This record covers compilation, synthetic behavior and local artifact checks. It does not establish compatibility with a current public game build or a running test-server session.

## Managed build and synthetic tests

The public package's `Recompilar.ps1` compiled both `ESP-LiveKd.exe` and `Abrir-ESP.exe` as deterministic x64 .NET Framework executables. The public `pruebas/Verificar.ps1` then compiled and ran all **24 suites successfully** in its final full run. `validation-results.json` contains that run's individual outputs and exit codes.

The new `AimCalibrationTests` suite passed nine cases: independent axes, calibrated step limits, feedback across asymmetric sensitivities at 20/30/60 Hz, invalid runtime values, repeated frames/release, reversal, migration, persistence and settings normalization. Seven missing-feature failures were reproduced before implementation. Synthetic feedback assumes the specified linear response; it is not a measurement of the game's sensitivity.

The existing suites cover selection, geometry, head/chest estimates, teams, profile data, bone transforms, visibility freshness, input guards, autofire state, discovery, camera ownership, projection, radar, retry/cadence and timer lifecycle.

## Timing-test history

`TimerResolutionTests` failed its latency threshold in two earlier full runs: a requested 17 ms sleep averaged about 30 ms while the timer lease was active. It passed in an isolated run at about 17.56 ms and in the final public-package full run at about 17.46 ms. The test and production timer implementation were not relaxed or changed to hide those failures.

The issue is therefore recorded as an **intermittent scheduling-test failure**. It is not proven to be a calibration regression, and the final passing run does not guarantee future latency. Windows documents that higher timer resolution is not guaranteed for fully occluded/minimized window-owning processes on Windows 11. That is a possible contributing condition, not a confirmed diagnosis of this test environment. Reference: [Microsoft timeBeginPeriod documentation](https://learn.microsoft.com/en-us/windows/win32/api/timeapi/nf-timeapi-timebeginperiod).

## Native checks

- The reduced runtime loaded the MemProcFS library and resolved the required exports using `Probar-LiveKd.ps1 -Mode Verify`.
- `NativeStress.cs` completed **6,000 parallel reads** against a generated 32 MB local fixture with **zero validation errors** using the adjusted LeechCore library.
- `patch_serial.py` reproduced the distributed adjusted DLL exactly from the pinned original; SHA256 matched.
- The MemProcFS source archive's version header declares 5.19.0.251, matching the distributed library's reported version.
- Both native source archives contain source material and no `.exe`, `.dll`, `.pdb` or `.sys` members.

The fixture contains generated bytes, not captured memory. Export loading does not initialize acquisition. Neither the managed suite nor the native fixture check read a running game's memory or sent real mouse input. The live acquisition path with the reduced public runtime remains unverified.

## Release checks

`release-files.sha256` lists the public release files with relative paths. The final ZIP is checked against those files for names, counts and byte hashes. It omits personal prerequisite configuration, machine reports, old ZIPs, generated logs, Microsoft binaries and kernel symbols. The only executable binaries supplied by the project are the overlay and its launcher; distributed native DLLs have their applicable source and notices documented separately.

The publisher-facing prose is English. Project publication text has been checked for tool-branding markers and personal source paths. Third-party source and license notices are preserved. The archive uses one flat root so extracting it does not create a second nested application directory.

## What remains unverified

- Actual game patch identity and base-reader offset compatibility.
- Automatic team, bone and raycast fields; the supplied target profile remains disabled.
- Real camera response to the selected manual calibration, including ADS/FOV changes.
- Aspect-constrained/off-center projection and per-monitor DPI changes.
- End-to-end LiveKD acquisition with the public package on another Windows build.
- Life/downed state, weapon muzzle obstruction and projectile trajectory.
- Detection status, live-game effectiveness and long-session stability.
- Runtime network behavior inside external vendor tools; no traffic capture was performed.

The package includes the observed limitations instead of presenting synthetic tests as evidence of a working current-patch or undetected cheat.
